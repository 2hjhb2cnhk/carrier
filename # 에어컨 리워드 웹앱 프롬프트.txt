현재 프로젝트 폴더의 `AGENTS.md`, `PROJECT.md`, `CHECKLIST.md`를 먼저 처음부터 끝까지 읽어줘.

이 프로젝트는 **Carrier GreenON**이라는 캐리어 에어컨 사용자를 위한 ESG 친환경 냉방 미션 + 리워드 웹앱이야.

`PROJECT.md`에 작성된 서비스 요구사항과 개발 순서를 기준으로 구현하고, `CHECKLIST.md`를 개발 진행상황 관리에 사용해줘.

한 번에 모든 기능을 임의로 축약해서 만들지 말고 반드시 단계별로 구현해줘.

개발 순서는 다음 원칙을 따라줘.

1. 먼저 기본 웹앱 UI와 화면 구조를 만든다.
2. 친환경 냉방 미션 기능을 구현한다.
3. 가상의 캐리어 에어컨 IoT 데이터를 이용해 미션 상태를 시뮬레이션한다.
4. 미션 성공 시 GREEN POINT를 지급하는 기능을 구현한다.
5. GREEN POINT 지갑과 포인트 사용내역을 구현한다.
6. GREEN REWARD SHOP과 상품 구매 기능을 구현한다.
7. Supabase를 연결해 회원가입/로그인과 실제 데이터 저장 기능을 구현한다.
8. 기존 localStorage 또는 임시 데이터가 있다면 Supabase 데이터 구조로 전환한다.
9. 사용자별 미션, 포인트, 구매내역이 분리되도록 구현한다.
10. Supabase RLS 정책을 적용해 사용자가 자신의 데이터만 접근할 수 있도록 한다.
11. 실제 캐리어 에어컨 API는 사용하지 않고 시뮬레이션 데이터를 사용한다.
12. 마지막 단계에서 Render에 배포할 수 있는 구조로 프로젝트를 정리한다.
13. 필요한 환경변수를 `.env.example`에 정리하고 비밀키는 소스코드에 직접 작성하지 않는다.
14. 배포 후 주요 기능이 정상 작동하는지 확인한다.

각 단계가 완료될 때마다:

* 해당 기능이 실제로 동작하는지 확인하고
* 기존 기능이 깨지지 않았는지 확인하고
* 완료된 항목을 `CHECKLIST.md`에서 체크하고
* 문제가 있다면 다음 단계로 넘어가기 전에 수정해줘.

디자인은 `PROJECT.md`에 정의된 디자인 시스템을 반드시 따라줘.

기본 디자인:

* White + Blue
* 밝고 귀엽고 친근한 느낌
* 둥근 카드와 버튼
* 모바일 우선 반응형 디자인
* 정상 상태는 Blue
* 성공 상태는 Blue 또는 Green
* 위험, 오류, 비정상 상태는 Red

특히 에어컨 상태 이상, 필터 점검 필요, 센서 오류, 미션 조건 위반, 포인트 부족 등의 상태에서는 관련 UI가 Red 계열로 변경되도록 해줘.

데이터베이스는 Supabase를 사용하고 최소한 다음 데이터를 관리할 수 있게 설계해줘.

* 사용자
* GREEN MISSION
* 사용자별 미션 참여 기록
* GREEN POINT
* 포인트 적립/사용 기록
* 리워드 상품
* 상품 구매내역
* 사용자 GREEN LEVEL
* 가상 에어컨 상태

Supabase를 연결할 때는 보안을 중요하게 생각해줘.

* service_role 또는 secret key를 브라우저 코드에 노출하지 않는다.
* 사용자별 데이터에 RLS를 적용한다.
* 인증된 사용자는 자신의 포인트, 미션기록, 구매내역만 볼 수 있도록 한다.
* 관리자용 데이터가 필요한 경우 사용자 권한과 분리한다.

최종적으로 사용자가 다음 흐름을 실제로 경험할 수 있어야 한다.

회원가입/로그인

→ 현재 날씨 및 가상 에어컨 상태 확인

→ 오늘의 GREEN MISSION 확인

→ 미션 참여

→ 에어컨 상태 시뮬레이션

→ 미션 성공

→ GREEN POINT 적립

→ GREEN WALLET에서 포인트 확인

→ GREEN REWARD SHOP 접속

→ 포인트로 상품 구매

→ 포인트 차감

→ 구매내역 확인

→ GREEN REPORT 확인

그리고 마지막으로 Render에 배포하여 외부에서 접속 가능한 웹서비스가 될 수 있도록 프로젝트를 구성해줘.

먼저 파일을 수정하기 전에 `AGENTS.md`, `PROJECT.md`, `CHECKLIST.md`를 분석하고, 현재 구현해야 할 개발 단계를 짧게 정리한 뒤 1단계부터 시작해줘.
